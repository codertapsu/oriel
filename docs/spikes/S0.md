# S0 — Build and release skeleton

2026-10-28 · macOS 27.0.1 (26A434), Xcode 27.1 (27A9275), SDK 27.0 · **Result: works, except the Homebrew tap, which waits for a release destination.**

The release pipeline follows Gitweaver and Mother Claude. It runs on this Mac, never in CI, with the shared `scripts/apple-credentials.env` (Apple ID plus app-specific password). `docs/RELEASING.md` is the runbook.

## Findings

- **XcodeGen writes literal versions.** Its generated Info.plist had `CFBundleShortVersionString` 1.0 and `CFBundleVersion` 1, so the app reported 1.0 (build 1) whatever `MARKETING_VERSION` said. `project.yml` now sets both from the build settings, and the release script checks the exported version against the tag.
- **`grep -q` under `pipefail` can fail on a match.** grep exits at the first hit and the writer dies of SIGPIPE, so the pipeline reports failure. That stopped the first rehearsal at the signature check, before any notarization; the script now captures the output before matching it.
- **The CLI target has `SKIP_INSTALL: YES`.** Without it Xcode also installs the tool under `/usr/local/bin` inside the archive, and the archive stops being an app archive that the export can handle. I set this before the first archive, so the failure was never observed here.
- **Notarizing twice costs little.** The app and the dmg each took well under the "1–5 minutes" the script warns about.

## Recommendation

Go. The pipeline is ready apart from publishing. Choose where releases go: a draft GitHub release, as Gitweaver and Mother Claude do, or PLAN §15's internal file host behind a private Homebrew tap. Then add the upload step and `bump-cask.sh`, and run §13.7's clean install on a macOS 26 VM.
