# OS quirks

This file records Apple APIs, SDK contents or OS behaviour that differ from docs/PLAN.md, or that differ between macOS 26 and 27. Add one row per finding, newest first, with the macOS build it was seen on (PLAN §0.3).

| Date | macOS (build) | Area | Finding | What we do |
|---|---|---|---|---|
| 2026-10-29 | 27.0.1 (26A434), SDK 27.0 | Pasteboard | macOS posts nothing when the general pasteboard changes: the shared cache holds no notification or notify(3) key for it (only the `com.apple.pasteboard.1` service name), and `changeCount` is the only signal. | Clipboard History compares `changeCount` after input events, app switches, wake and the panel opening (`PasteboardWatcher`, PLAN §7.9), never on a timer. |
| 2026-10-29 | 27.0.1 (26A434), SDK 27.0 | Pasteboard privacy | Privacy & Security has **Paste from Other Apps** (`PrivacyPasteboardService`, link anchor `Privacy_Pasteboard`). `NSPasteboard.accessBehavior` (15.4+) is `.default` until a programmatic read of another app's copy first makes macOS ask, then `.ask`, `.alwaysAllow` or `.alwaysDeny` as set in that pane; an app appears there only once macOS has asked about it, and the pane warns that a change may apply only after the app quits. The SDK documents only the detect APIs (`detectPatterns(for:)` and the like) as reading without asking; whether reading types asks was not tested, to avoid prompting on this Mac. | Clipboard History reads while `.alwaysAllow` or `.default`, stops at `.ask` and `.alwaysDeny` and counts the copies it missed; the first time a copy is let through it opens the pane once. Oriel's own copies are announced by `SharedUI.Pasteboard` and kept without reading the pasteboard. |
| 2026-10-29 | SwiftFormat 0.64.4 | Tooling | The `redundantSelf` rule removes `self.` inside an `os.Logger` message's interpolation, which is an autoclosure, and the build then fails ("reference to property … in closure requires explicit use of 'self'"). | Bind the value to a local before logging it, as the rest of the code already does. |
| 2026-10-29 | SDK 27.0 (Xcode 27.1) | QuickLookUI | `QLPreviewPanel.h` has no nullability or concurrency annotations. The `QLPreviewPanelController` methods (`acceptsPreviewPanelControl:` and the others) are a category on `NSObject`, so they are nonisolated, and `QLPreviewPanelDataSource` is not main-actor. | The editor's window controller overrides them `nonisolated` and works inside `MainActor.assumeIsolated` (AppKit calls them on the main thread), and conforms to the data source with `@preconcurrency`. |
| 2026-10-29 | 27.0.1 (26A434) | TCC | macOS keeps one Accessibility entry per bundle ID, holding the code requirement of the build that asked first. A Debug build (Apple Development) had asked first, so the notarized release (Developer ID, same bundle ID) was refused although System Settings showed Oriel switched on; tccd logged `Failed to match existing code requirement for subject com.yourcompany.oriel and service kTCCServiceAccessibility`. Screen Recording, camera and microphone, first asked for by the release, worked. On 27, posting events composes to the same entry (`kTCCServicePostEvent` → `kTCCServiceAccessibility`). | Debug builds have their own bundle ID, `com.codertapsu.oriel.debug`, shown as "Oriel Debug". The permission list tells the user to remove Oriel with − and add it again when its switch is on but not honoured. |
| 2026-10-29 | 27.0.1 (26A434) | System Settings | Privacy & Security calls the Accessibility pane **Device Control and Data Access** (key `ACCESSIBILITY` in `SecurityPrivacyExtension`); Screen Recording is "Screen & System Audio Recording". Accessibility has no "until it is quit" prompt, so a grant applies to the running app; Screen Recording and Input Monitoring keep theirs. The `Privacy_Accessibility` and `Privacy_ScreenCapture` link anchors still work. | `PermissionKind.settingsPaneName` names the pane for the running macOS; permissions are re-read when any app comes to the front and when `com.apple.accessibility.api` is posted, not only when Oriel is activated. |
| 2026-10-29 | 27.0.1 (26A434) | Shell | In zsh, the default shell, `log` is a builtin (`log: too many arguments`), so `log show` and `log stream` silently do nothing. | Call `/usr/bin/log`. tccd's decisions appear with `/usr/bin/log stream --level debug --predicate 'subsystem == "com.apple.TCC"'`; they are not kept for `log show`. |
| 2026-10-29 | 27.0.1 (26A434) | LaunchServices | Every built copy of the app registers `oriel://` and the `.oriel` type: seven copies were registered (DerivedData, `build/Release`, `build/install`, `dist/`, `dist/dmgroot`, an archive and a mounted dmg). `open oriel://settings` launched the stale 0.1.0 copy in `build/Release` instead of handing the URL to the Debug build already running. | `make install` unregisters its export and registers the installed copy; BUILDING.md troubleshooting shows `lsregister -u` / `-f`. |
| 2026-10-29 | 27.0.1 (26A434) | ScreenCaptureKit | A 10 s `SCRecordingOutput` recording of the static lock screen lasted 10.1 s, and one paused from 3 s to 5 s joined into 8.1 s: the movie follows wall time even when no frame changes. Captures and recordings work while the screen is locked and show the lock screen. | `verify-recording.sh` expects ± 0.2 s and runs fine unattended. |
| 2026-10-29 | 27.0.1 (26A434) | top(1) | In logging mode (`top -l N -s 1 -stats cpu,idlew`), `IDLEW` is the process's idle wake-ups since launch, not per sample, and the first sample's `%CPU` has no baseline. | `idle-cpu.sh` skips the first sample and reports the wake-ups added during the run. |
| 2026-10-28 | 27.0.1 (26A434) | Windows | Besides real windows, every app owns per-display menu-bar windows (30–33 pt tall, layer 0, off screen) and 500×500 off-screen helpers in `CGWindowListCopyWindowInfo`. | The switcher lists another Space's window only after an Accessibility element proves it is a real window. |
| 2026-10-28 | 27.0.1 (26A434) | Accessibility | While the screen is locked, Accessibility lists no real windows. | The window store shows none and re-reads everything when the session comes back. |
| 2026-10-28 | 27.0.1 (26A434) | Accessibility | Remote-token element ids are not small: a Brave window sat above id 1000, where the search stops. Each app's first Accessibility request costs 10–60 ms. | Such a window appears once its Space has been visited; accessory apps are asked only when they own a visible or Space-assigned window. |
| 2026-10-28 | 27.0.1 (26A434) | Vision | `RecognizeTextRequest` labelled English lines `fr-FR` in tests. | OCR takes each block's language from `NLLanguageRecognizer`, not Vision. |
| 2026-10-28 | 27.0.1 (26A434) | FoundationModels | Supported languages are listed with regions (`ja-JP`), so looking up a bare `ja` fails. | The provider matches on the language code. |
| 2026-10-28 | 27.0.1 (26A434) | FoundationModels | The context window is 8,192 tokens on 27; 4,096 is the value for 26. Error types also differ between 26 and 27. | Chunks are capped at a quarter of the reported size, and an overflowing chunk is halved and retried; both error types are handled. |
| 2026-10-28 | SDK 27.0 | Translation | The Translation module is built in Swift 5 language mode, so `prepareTranslation()` trips Swift 6 sendability checks. | `@preconcurrency import Translation` where the download sheet calls it. |
| 2026-10-28 | 27.0.1 (26A434), SDK 27.0 | AVFoundation | The macOS 27 SDK deprecates `AVAssetWriter`'s `add`/`startWriting`/`append` and the pixel-buffer adaptor in favour of the macOS 26 receiver API, and `AVMutableVideoComposition` as of 26.0. | Recording uses `AVVideoComposition.Configuration`; the test helper that writes movies uses the receiver API. |
| 2026-10-28 | 27.0.1 (26A434) | AVFoundation | A constant-frame-rate export without an explicit time range stopped one frame after the last frame when several exports ran at once. | "Export CFR" always passes the full time range. |
| 2026-10-28 | 27.0.1 (26A434) | ImageIO | A GIF written with one shared palette keeps every frame in memory until it finishes: about 1.2 GB for 300 frames at 800×450. One palette per frame stays near 20 MB. | The GIF exporter writes per-frame palettes. |
| 2026-10-28 | 27.0.1 (26A434) | Menu bar | An app's `NSStatusItem` has no window in `CGWindowListCopyWindowInfo`. With Oriel's icon visible on all three menu bars, no window belonged to its pid. The menu bar itself is Window Server windows at layer 24 (alongside a `MenuBarAgent` process), and the only layer-25 window belonged to `LinkedNotesUIService`. | Window enumeration (S1) never sees status items, which suits the switcher. To check a status item, take a screenshot of the menu bar; in global coordinates, displays taller than the main one have negative y. |
| 2026-10-28 | SDK 27.0 (Xcode 27.1) | SDK | The Carbon (HIToolbox) headers are ISO-8859-1. grep in a UTF-8 locale silently skips them, which made `RegisterEventHotKey` look missing during S8. | Search them with `LC_ALL=C grep -a`. The API is present and not deprecated. |
| 2026-10-28 | 27.0.1 (26A434) | Rosetta | Rosetta was not installed on the dev Mac. `softwareupdate --install-rosetta --agree-to-license` installed it without admin rights. | Nothing more. `make universal-check` needs it, and CI must install it the same way (Appendix F, item 7). |
| 2026-10-28 | 27.0.1 (26A434) | Testing | `automationmodetool` reports that Automation Mode is off and that this Mac "requires user authentication to enable Automation Mode". XCUITest runs need Automation Mode, so a UI test run would stop at an admin-password prompt. Not tried, to avoid an unattended prompt. | `make test` skips `OrielUITests` unless `ORIEL_UI_TESTS=1`. One-time fix: `automationmodetool enable-automationmode-without-authentication` (admin). |
| 2026-10-28 | 27.0.1 (26A434), SDK 27.0 | SDK | The SDK ships `Translation.framework`. A local Swift module named `Translation` would shadow it and could not import it, which the Apple Translation provider has to do. | The package is named `OrielTranslation`. |
| 2026-10-28 | 27.0.1 (26A434) | Filesystem | The data volume is case-insensitive APFS, the macOS default. `Oriel.app/Contents/MacOS/oriel` is therefore the same path as the app's executable `Contents/MacOS/Oriel`, and names that differ only by case collide in Xcode's build folders (`Oriel.build` and `oriel.build`, `Oriel.swiftmodule` and `oriel.swiftmodule`). The same applies on users' default volumes. | The CLI is embedded at `Contents/Helpers/oriel`. Its target is `oriel-cli` and its Swift module is `OrielCLI`, while the binary is still `oriel`. |
